# 业务流程、角色 RACI 与状态机
> **控制状态：执行候选 / 尚未获各 Owner 与 Gate 批准。** 本包是供研发、评审、拆解任务使用的工程设计输入，不等同已冻结的 AEOS 标准。
> **来源等级：** [B] 上传的 AEOS V7.2.2 合订版；[C] 已核查 HLC 仓库代码（关键文件片段）；[D] 2026-10-15 V3.0 DEMO/讨论；[P] 本次新增的设计建议；[V] 生产部署或外部开源组件待验证。

## 1. 维修/后勤申请（首期真实闭环）
**流程**：员工 M10 新建 → M01 Guard 检查 → M07 受理 → 行政分派 → 执行人处理与上传证据 → 申请人/有权限验收人确认 → M07 关闭 → M02 归档 Event/Result/Evidence → M10 显示报告。

### 状态机（候选）
`DRAFT → SUBMITTED → TRIAGED → ASSIGNED → IN_PROGRESS → AWAITING_ACCEPTANCE → CLOSED`；例外：`NEEDS_INFO`、`REJECTED`、`CANCELLED`、`REOPENED`。
- SUBMITTED：仅请求人本人或委托人提交；生成 immutable request_id。
- ASSIGNED：必须有 assignee、SLA、scope 与通知结果。
- AWAITING_ACCEPTANCE：必须有处理结果和至少一个适用证据引用。
- CLOSED：必须验证人、时间、ResultRef；不得由无授权 Agent 强制关闭。
- REOPENED：关联原 ResultRef，补充新 evidence，不覆盖历史。

## 2. 请假/考勤申请（次条闭环）
`DRAFT → SUBMITTED → POLICY_CHECKED → APPROVAL_PENDING → APPROVED / REJECTED → APPLIED → ARCHIVED`；申请人与审批人不能在需要职责分离时为同一人。考勤生效由 M07 专业系统完成，M10 不计算薪资或工时。[P]

## 3. 入职/调岗/离职（高风险门禁）
`REQUESTED → HR_CHECKED → BUSINESS_APPROVED → PERSONNEL_APPROVED → M01_CHANGE_PENDING → M01_CONFIRMED → HANDOVER_VERIFIED → ARCHIVED`。任何含人员身份或权限变化的动作必须在 M01 完成受控生效；若 M01 拒绝或超时，保持 PENDING 不得伪造“已生效”。离职须检查未完待办、资产归还、授权撤销、会话终止和离线数据清除。[B/P]

## 4. RACI（R=执行，A=最终负责，C=咨询，I=知会）
| 工作 | 员工 | HR/行政专员 | 部门负责人 | M01 Owner | M02 Owner | M10 Owner |
|---|---|---|---|---|---|---|
| 申请发起 | R | I | I | C | I | A(交互) |
| 后勤派单及业务验收 | I | A/R | C | C | I | I |
| 人事异动专业审批 | I | R | A(业务审批) | C | I | I |
| 身份和权限授权变更 | I | C | C | A/R | I | I |
| 事件和证据合同化 | I | R(专业输出) | I | C | A | C |
| 工作面装配与反馈 | I | C | I | A(授权) | C | R |
| Agent 专业建议 | I | A(专业验收) | C | A(授权) | C | R(入口) |

## 5. 任务异常规则
超时 → M07 超时事件 + M10 异常提醒；未授权操作 → M01 拒绝并 M02 审计；接口不可用 → 有限重试，达到上限入死信/人工处置；异动后旧岗位任务 → 转派或冻结并保留轨迹；数据不一致 → 不自动覆盖专业主数据，交 Owner 复核。[B/P]
