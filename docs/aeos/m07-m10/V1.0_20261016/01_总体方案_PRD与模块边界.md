# M07 HLC + M10 POMS 总体开发方案 / PRD
> **控制状态：执行候选 / 尚未获各 Owner 与 Gate 批准。** 本包是供研发、评审、拆解任务使用的工程设计输入，不等同已冻结的 AEOS 标准。
> **来源等级：** [B] 上传的 AEOS V7.2.2 合订版；[C] 已核查 HLC 仓库代码（关键文件片段）；[D] 2026-10-15 V3.0 DEMO/讨论；[P] 本次新增的设计建议；[V] 生产部署或外部开源组件待验证。

## 1. 产品目标与成功标准
面向恒剑，以“人事行政管理端（M07）+员工极简个人端（M10）”为第一条端到端范例。员工在 M10 发起申请、收待办、提交必要资料、查看过去报告；M07 专业处理、审核及验收；M01 权限决策；M02 存证；M13 Agent 提供辅助。[B/D/P]
**首条 MVP 闭环：** 员工报修或请假 → M10 发起 → M07 接收、派单/审批 → M01 Guard → M07 写业务结果 → M02 Event/Result/Evidence → M10 查看经授权的完成报告。[P]
**第二条验证闭环：** 入职、调岗或离职 → M07 业务流程 → 人工核验 → M01 任职/授权生效 → M10 更新 role template、清空失效会话与离线缓存。[B/P]

## 2. 架构事实边界（不得突破）
| 系统 | Own | Must Not | 关键输出 |
|---|---|---|---|
| M00 GOV | 基线、Owner、Gate、签批 | 业务事实与专业审批 | GateDecision、受控清单 |
| M01 Kernel | canonical person/org/position IDs、Permission、Policy、Guard、撤权 | HR 专业事实 | AuthContext、GuardDecision |
| M02 EDP | 事件、结果、证据、审计、Trace、契约版本 | 业务专业对象主数据 | EventRef、ResultRef、EvidenceRef |
| M07 HLC | 招聘任用、人才能力、培训、绩效、HR/后勤服务请求与结果 | 第二套身份/权限权威 | HRServiceRequest、LogisticsRequest、HRResult |
| M10 POMS | ui_manifest、role_template_ref、personal_context、待办/异常、个人结果引用 | Customer/Order/Quote、HR 专业对象、薪酬、正式岗位主数据 | PersonalWorkspace、WorkItemProjection |
| M13 Hub | Agent Workforce、Skills/Tools、成本、生命周期 | 绕过人审/Guard直接改业务事实 | AgentSession、SkillInvocationRef |

## 5. 关键用户与权限
员工：本人申请、本人任务及本人结果。人事专员：被分配 HR 服务和已授权档案。行政后勤专员：后勤请求与资源。部门负责人：本部门业务审批及摘要；不得默认看员工敏感字段。经营决策者：EBMS 的已授权汇总与待决事项，不直接覆盖 HR 专业结果。审计员：审计引用、最小暴露、独立授权。个人/专业 Agent：按 M13 注册及 M01 Guard 授权。[B/P]

## 6. 非功能要求
租户与对象级授权、字段级脱敏、不可逆动作 maker-checker；请求幂等、重试与 Outbox；证据追加/版本化；时区与业务日期一致；移动端常见 360px 宽度可用；任务列表性能基线需在 G1 冻结；日志不得写入证件号、薪酬明文或密钥。[B/P]

## 7. 明确不做
不在 M10 制作第二套 HR 系统；不让 M07 直接修改 M01 canonical identity；不从前端提交“管理员角色”作为授权依据；不把 `backend-python/routes/tasks.py` 内存上传进度当作持久业务任务；不在首期做薪资计算/自动录用/自动离职/自动设备操控；不直接复制 GPL/商业许可代码。[C/P]
